# FCIS — Official OpenAPI dependency and transferable provider examples

**Status:** organization-owned agent/engineering procedure, introduced 1 November 2026. **Authority boundary:** FCIS governs the *use* of an external API, not the vendor's schema, model catalogue or semantics. A vendor-specific adapter is dependent on its provider's **official** OpenAPI where one exists. Never turn OpenAI's specification into FCIS's own protocol.

## Required implementation contract

1. **Identify the official source** before changing an external HTTP or event-driven provider adapter: publisher/repository, exact immutable upstream commit or released version, original file URI, OpenAPI version, SHA-256 of the actual official file, and relevant endpoint/event schema identities. A public documentation page or SDK-shaped guess is not an adequate source pin. If no official OpenAPI covers the operation, state that gap and use the vendor's exact official protocol/SDK references; do not fabricate coverage.
2. **Keep a reproducible, minimal provider projection.** Extract only transitive upstream schemas used by the adapter; retain their unchanged definitions, full upstream file digest and projected bundle digest. Automated tests must work offline against the locked artifact. A separate reviewed drift check must compare projection and transitive closure to the real upstream bytes, not merely to hand-authored fixtures. Version dependency updates explicitly; never float a provider `main` branch in acceptance.
3. **Validate the actual request constructors and response/event handlers** against those source schemas. For streamed protocols, validate the consumed event envelope and documented lifecycle separately; OpenAPI alone does not certify WebSocket ordering, connection lifecycle, model availability or generated-media quality. Check relevant official examples and negative cases, including absent required fields and unsupported variants.
4. **Disclose upstream schema defects narrowly.** Do not silently modify or fork the original vendor schema. Preserve the original pinned bytes. A small, tested compatibility exception may cover only an independently demonstrated discrepancy between official examples/documentation, observed successful use and the published schema. Record its precise path, input shape, scope and removal trigger. Fail closed on unrelated validation errors.
5. **Promote an accepted example as a bounded reusable regression.** Link the actual source-owner Git revision, successful terminal request/receipt, exact source, media or result digest, and independent witness as available. Preserve provider-supplied published event examples as separate synthetic fixtures. **Never assert that a unit-test example replays real provider traffic unless an authenticated sanitized trace was retained.** Transport success, valid schema, content fidelity, authorization, usability and artistic acceptance are separate predicates. Promote the reusable procedure to the *existing* canonical FCIS Skill with its reviewed tree digest and GitHub distribution, not a parallel skill/API client.
6. **Conserve authority.** Runtime capabilities remain typed-Kit owned, Git is development, source-owned adapters handle credentials and external calls, and publication requires its separately governed release. An official vendor schema cannot grant rights, voice identity, editorial approval, accessibility or production admission.

## Verified first example — Satzfunk Realtime / British Vergil

- Upstream: `openai/openai-openapi` commit `c2aecc2fbe1ddff3e7500a0eaa5c2bc4c19c5318`, OpenAPI 3.1 `openapi.json` SHA-256 `d80bb28992f6c2a86876d866dcae0b1f15e130de94238592bc57a4a579448b5f`.
- Source-owner implementation: `Fountain-Coach/Satzfunk` `src/openai-realtime-voice.mjs` plus `src/openai-realtime-contract.mjs`. A checked-in 67-schema **unaltered upstream projection** validates two emitted client event types and five consumed server event types; `npm run contract:check` runs without a live API call, while `node scripts/check-official-openapi.mjs --source <pinned-openapi.json>` independently checks the exact official file and full projection closure.
- Official schema issues: Realtime `response.create` `conversation: "none"` matches both branches of an overlapping upstream `oneOf`. The source-owned adapter retains the upstream projection unchanged and narrowly normalizes this one shape to `anyOf` **only while compiling validation**, refusing unexpected upstream shape changes. Separately, an official `response.done` example contains `status_details: null` despite an object-only schema: this remains a documented upstream example/schema inconsistency, **not** a second admitted runtime bypass. Both require review on any future upstream pin.
- Prior **real** host use: 1 November 2026 one source-locked `gpt-realtime-2.1-mini`/`marin` recording of the original 554-character Vergil passage, 34.2-second private WAV SHA-256 `0f6219c329e4dec9b46799c1a2b90b846340e6c3d23b8a008b5254d89f1790f6`. This is proof of a completed API/media transport; no sanitized real event trace was saved for replay. The retained source-owned example is `examples/vergil-openapi-realtime-transport.v1.json`; wire fixtures are synthetic and checked against official schemas, not a fabricated real trace.
- **Failed literary acceptance:** the author's audition identified an American female voice, incompatible with mature British Vergil. This remains a *rejected voice*. Official OpenAPI validation must never override casting, literary or auditory acceptance. Public production and paginated Linotype remain untouched.
