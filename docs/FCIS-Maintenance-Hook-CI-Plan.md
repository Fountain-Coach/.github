# FCIS maintenance and ubiquitous Git-hook CI — implementation plan

**Pinned:** 18 November 2026 · **Owner:** Fountain Coach · **Source authority:** [FCIS-STACK.md](../FCIS-STACK.md), peer [FCIS-OPENAPI.json](../FCIS-OPENAPI.json), [dated critical review](FCIS-Spec-OpenAPI-Critique-2026-11-18.md). **Implementation language:** portable POSIX `/bin/sh` for orchestration/hooks; Go for the FCIS runtime; Python, Go and format-specific validators may be invoked as deterministic tools. Avoid an unnecessary new CI service.

**State at pinning:** This is a **source-owned maintenance plan**, not a claim of installed owner Git server hooks, source-tested Go conformance or live production cutover. The existing `.githooks/pre-commit` checks canonical Skill digests; `pre-push` checks digests and attempts recoverable backup; `post-commit` mirrors admitted Skills into the existing plugin; GitHub `.github/workflows/test.yml` runs Skill/projection/Python checks on GitHub-hosted Ubuntu. GitHub main ruleset still requires the hosted `build` check. Its continued enforcement MUST NOT be silently removed before an owned substitute is accepted.

## Non-negotiable design

1. **One shared test entrypoint.** `scripts/fcis-ci.sh [source|go|full]` is the versioned POSIX shell runner. `source` validates canonical Skill digests, nine packaged mirrors, root OpenAPI syntax and semantic source regression, and the correct base/head changed-file diff. `go` runs only when an actual Go source revision and isolated native build target are supplied; fixed Go tests use `go mod verify`, `go vet`, `go test -race -count=1` and `go build`. Fail closed if the requested tool is missing; no success from skipped mandatory checks. Preserve current Go Build Instrument admission semantics for live Host dispatch.
2. **Same checks everywhere.** Local `pre-commit` may run the fast source check; `pre-push` runs complete source validation and uses the existing optional recovery snapshot. GitHub Actions becomes one consumer of `scripts/fcis-ci.sh`, not an alternative policy. Use a real `git diff --check <base>...<head>` on candidate branches; do not infer formatting success from a clean worktree. Git-hooks installation via `git config --local core.hooksPath .githooks` is per clone; scripts do not make it universal by existing in Git. **Client hooks are bypassable** and must never substitute for owner server-side admission.
3. **Server-side enforcement is required for autonomy.** An owner-controlled *bare Git origin* installs a `pre-receive` hook separately using an administrator-reviewed immutable hook. The hook reads `old SHA new SHA ref` from standard input and rejects unauthorized direct updates/deletion/rewriting of `refs/heads/main`, unsafe refs and other declared policy violations. Never trust a contributor-side `pre-commit` or `pre-push` hook as branch protection. No hook sourced from an unreviewed incoming branch may execute with bare-repository privileges.
4. **Candidate execution is unprivileged.** Validate exact incoming candidate commit in an isolated checkout/worktree or disposable container under a constrained service identity without issuer signing keys, deploy credentials or production Store write access. Verify candidate and expected base SHA, enforce bounded resource/time limits and serialize per-repository promotion. Keep the **reviewed runner policy** outside the untrusted candidate until it is accepted; a malicious branch must not replace its own safety checks.
5. **Owner-controlled promotion.** An explicit signed/authorized promotion procedure checks `candidate SHA + expected old main SHA + complete PASS receipt`, then atomically updates `main` with compare-and-swap semantics. Deny stale candidates or a changed base, refuse success on partial tests, retain source and artifact SHA-256 and failure logs, and keep failed candidate branches without modifying `main`. This is not permission to circumvent GitHub's existing branch protection: adoption must first be independently proved on an actual owner bare origin.
6. **Recovery is separate.** Preserve `scripts/git-disaster-recovery.sh`, offline bare mirror, tested full Git bundles, and signed immutable release/rollback records. A removable backup disk's absence is a warning for ordinary local commits, not a fabricated failed source test. Verify at least one actual offline restore before declaring the new origin independent.
7. **Authority boundaries.** Git stores source intent; the verification receipt proves exactly the tests run; FountainStore proves effects; Caddy/public HTTPS proves an activated release; OAuth owner authority signs permitted release transitions. Neither a green Git check nor a successful hook becomes a customer grant, automatic FCIS deployment or legal certification.

## H2 implementation surface — source-owned portable checks

H2 provides `scripts/fcis-ci.sh` in **one canonical organization Git repository**, invoked by existing client `.githooks/pre-commit` (`staged` mode), `pre-push` (`source` and push-range `diff`) and the two existing read-only GitHub workflows (`source`). Local hooks remain per-clone advisory; the current GitHub ruleset still requires the same `build` context while H3 owner bare-origin enforcement is **not installed**.

The source entrypoint is explicit and POSIX: `sh scripts/fcis-ci.sh staged` checks staged whitespace plus Skill integrity; `sh scripts/fcis-ci.sh source [BASE HEAD]` verifies canonical root JSON, nine digest/mirror trees, the organization regression suite and a committed-base Git diff; `sh scripts/fcis-ci.sh diff BASE HEAD` verifies an exact proposed range. In GitHub Actions the workflow supplies `FCIS_CI_BASE` and `FCIS_CI_HEAD` from PR/push event data and checks out full history. Missing or malformed source/verification input fails closed, and a passing job proves these exact checks only.

Native Go verification is a **separate explicit mode**: `FCIS_CI_GO_MODULE=/isolated/checkout/apps/... FCIS_CI_GO_SHA=<exact-commit> FCIS_CI_GO_CACHE_ROOT=/isolated-cache sh scripts/fcis-ci.sh go`. It requires an already provisioned Linux/external build host, clean pinned Go Git checkout and offline local cache; then runs `go mod verify`, `go vet ./...`, `go test -race -count=1 ./...` and `go build ./...`. The organization GitHub source workflow does **not** silently run native Go from absent unrelated repository modules; this remains H4 implementation acceptance, not an H2 claim of Go conformance.

**H2 regression:** `skills/tests/test_fcis_posix_ci.py` exercises POSIX shell parsing, offline fixture success, invalid OpenAPI JSON, plugin mirror failure, Python test failure, multi-commit diff whitespace, staged whitespace, incomplete CI base/head pair and unconfigured Go refusal. These tests use disposable independent local Git fixtures, not a live owner bare Git origin. Local recovery, two-commit Skill projection and production runtime controls are deliberately unchanged.

## H3 source implementation and operational gap

[H3 owner-controlled Git procedure](FCIS-Owner-Git-H3.md) defines **two separate reviewed controls**. A bare Git origin's `hooks/pre-receive` rejects direct updates to `main` and fixes each `candidates/<id>` ref after creation. An operator-only `scripts/fcis-git-promote.sh` checks an exact SHA/old-main/repository/policy/expiry bound owner Ed25519 approval created on the separate owner device by `scripts/fcis-git-approve.sh`, then executes H2 CI on an independently checked-out commit in a networkless Bubblewrap user/PID namespace with read-only source, bounded resources and source-hashed validators. Only a full pass can atomically `git update-ref` compare-and-swap `main`; private source and promoted receipts include exact digests. A changed main, unsigned intent, failing validator or source refusal leaves main unchanged.

**Source evidence:** the Ubuntu Mac mini ran the disposable bare-Git/offline Ed25519/Bubblewrap regression matrix **11/11 PASS** on 18 November. These are *temporary* repositories under a cache path, not the operational Git receiver. The real organization checkout on Ubuntu was originally shallow, no dedicated `fcis-git` / `fcis-ci` OS accounts were present, and the remote execution channel blocks OS administrator commands. Do not silently use the sole owner account's recovery mirror or a user-writable test origin as a separately secured service. Actual OS provisioning, forced receive-pack ingress, protected origin, owner signer's real device/key, independent offline restore and mirror continuity are distinct **H3 live acceptance** still required; GitHub main branch protection stays intact.

## Per-slice exit contract

Every implementation task reads this plan and the [dated critique](FCIS-Spec-OpenAPI-Critique-2026-11-18.md), resolves **one** item or tightly coupled group, names source repository and pinned revision, and states *observed*, *source-tested*, *reviewed*, *installed*, *released*, and *live-accepted* separately. Cite exact test command, exit code, artifact SHA, proof record and next unmet acceptance predicate. A timeout, absent grant or missing owner-host installation is not silently converted into success. Do not widen the original [priority-one Go cutover DoD](../FCIS-STACK.md#7-production-deployment-and-finite-dod--priority-one) because this maintenance plan has further phases.

## Recurring maintenance ownership

**On each proposed release:** verify exact OpenAPI/Go compatibility, native security tests, Store recovery/refusal behavior, dependency integrity, no secrets, release manifest/rollback and impacted Skill projections. **Weekly:** review vulnerabilities and operating failures, classify relevance and owner, avoid changing stable code solely because a new advisory exists. **Monthly:** review upstream MCP/OAuth/WebAuthn/Go specifications and [European regulatory applicability](FCIS-EU-Regulatory-Maintenance.md); compare actual sources, effective dates and affected deployment. **Quarterly:** independently restore Git bundle and Store backup into isolated targets and verify provenance/recovery. Record skipped/unavailable checks as NOT_ESTABLISHED; a written cadence is not a running scheduler.

## Final audit criteria

- Root architecture, OpenAPI, critique and plan cross-link without a second source of authority.
- Every amended canonical Skill has one exact SHA-256 in `skills/openai-distribution.json`; all nine source trees match the **same existing plugin** mirrored trees; its plugin patch version increments once and `pluginId` is unchanged.
- Existing organization unit tests plus new focused policy/hook tests run through the shared runner where implemented. GitHub status is reported as one independent, derived witness, not an owner-operated origin proof.
- Actual Git main readback, installed ChatGPT plugin version, owner bare Git server behavior and running Go issuer are reported as distinct statuses. No invented release or legal-compliance claims.
