# FCIS Publication and Source Policy

Fountain Coach distinguishes public publication from private implementation.

Public repositories and sites MAY publish reviewed, sanitized projections: public contracts, capability identities,
release boundaries, AX/VRT evidence, provenance, and human-readable documentation. They MUST NOT publish secrets,
credentials, private store records, personal data, manuscript material, private fixtures, deployment access, or
unreviewed claims.

Private implementation repositories remain private by default. A public document MUST NOT present a private repository
as if it were readable by everyone; it must state the access requirement and link to the public governance or
publication projection instead. A GitHub 404 for a private repository is not a publication experience or a security
policy explanation.

Making a repository public is a separate decision requiring an explicit visibility decision, license review, secret and
dependency scan, fixture/data scrub, and maintainer approval. Publishing a sanitized projection does not authorize
publishing its implementation.

For the Reframe publication, the normative policy is [Reframe governance Chapter 44](https://github.com/Fountain-Coach/Reframe-Refactoring/blob/main/docs/44-publication-and-source-policy.md),
and the public projection is [The Book of Reframe](https://github.com/Fountain-Coach/book-of-reframe).
