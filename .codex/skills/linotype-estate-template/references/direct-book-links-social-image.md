# Fountain Press direct-book identities and first-chapter sharing

**Owner:** Fountain Coach / Fountain Press, with each source book retaining its author/revision/rights. **Scope:** an admitted illustrated book/collection (not unrelated domain Governance). **Authority:** source owner for content and rights; existing Linotype for Reading; EstatePublisher for stage/production effects; this Skill for repeatable procedure, not publisher execution.

## What readers and crawlers must see

Every admitted book has an immutable, directly openable HTTP path under the existing Press book routes, e.g. `/estate/books/first-readings/`. The route serves **the same semantic, paginated Fountain Press Reader and book contents** as the Bookshelf, not a separate design, a video grid or a redirect to a hash-only URL. The Bookshelf itself exposes the direct book link visibly and accessibly. Responsive composition and page navigation stay with the existing Reader. Preserve a stable canonical URL across artwork revisions; generate a new immutable static release, not a new book identity, after a source change.

**Metadata arrives in the first HTTP response, without JavaScript.** Each book route has one canonical link, exact `og:type=book`, `og:url`, `og:title`, `og:description`, `og:image`, `og:image:alt`, `og:image:width/height`, `twitter:card=summary_large_image`, `twitter:image`, and a source-bound Schema.org `Book` JSON-LD object with `hasPart` identifying the first eligible illustrated chapter. Social networks cannot use a fragment-only `#/read/<book>` route as unique book metadata: fragments are not sent to servers.

**First chapter's actual illustration is the social visual.** From the book's *admitted, ordered chapter/illustration inventory*, select the earliest illustrated chapter/entry. Unillustrated editorial prefaces do not authorize a fabricated image or moving an unrelated later figure into the text. For eligible source-authored illustrated chapters, derive the book's 1200×630 raster share image from that chapter's first admitted illustration, without aspect distortion or an invented banner. Keep its real source position in the Reader unchanged. Record original source image path, SHA-256, alt/credit/rights, chapter ID, social derivative SHA-256/dimensions and composition preset in the same versioned book catalogue. If a book has no admitted illustrated chapter, use the existing source-pinned landscape **first Linotype folio** fallback only when accepted; otherwise refuse *social* completion without failing the existing Reader.

### Source manifest and canonical regeneration

Use the current Fountain Press source Gallery/Bookshelf to derive membership, chapter order and image identity. Never guess which image is first from file timestamps, an old Facebook post or a general logo. The human book page, machine-readable `/estate/books/catalog.json`, and per-book JSON-LD **must come from the same source revision**. The normalized catalogue binds book ID, canonical HTTPS URL/path, source owner/revision, first illustrated chapter ID, original figure/source SHA-256, derivative SHA/dimensions/alt/credit/rights, and *actual* publication status.

Rebuild the book routes and social derivatives **whenever** a book's membership/order, first eligible figure/source bytes, alt, credits, rights, or canonical URL changes. A new source revision invalidates stale artefacts even when the visible book appears similar. Use a deterministic, checked-in compiler in the Press source repository, not an agent's ad-hoc HTML editing. Invoke it from the existing publication build/preflight, comparing exact source/target SHA-256 and refusing stale output. A Skill itself does not schedule future work, mutate an installed marketplace automatically, or grant public rights.

**First accepted example:** the private 11 November 2026 `Orange Dot` production-shaped Bookshelf has exactly `Essays · First Readings · Orange Dot`, with no separate Governance/Works/Scores books. Direct book paths are `/estate/books/essays/`, `/estate/books/first-readings/`, and `/estate/books/orange-dot/`. The selected source visuals are respectively the first illustrated `Client-Centered` essay (`essay--client-centered`), the first illustrated First Reading `Anweisung an den Schmerz` (`solstice-reading-01--2025-12-22-anweisung-an-den-schmerz`), and Orange Dot's opening `Solstice` (`orange-dot--2025-12-21-solstice`). Do not generalize these exact names/counts to other books, and do not make Orange Dot public merely because its preview was composed.

## Verify actual browser and crawler behavior

1. Inspect **current production** before staging: source owner/release/Reader script, actual rendered Bookshelf, and public routes. Inspect canonical staging independently. Pin exact predecessors and source/figure SHAs.
2. Compose the static book URLs and existing Linotype Reader from one source. Add a visible accessible direct-link anchor to the Bookshelf; use the same active compositor/app. Derive raster JPEG/PNG for each book from its own first eligible illustrated chapter. Keep the master image, Figure source placement, all manuscript blocks and original imagery unchanged.
3. Fetch each book path with an ordinary HTTP client, with no JS execution. Verify HTTP 200, exactly one canonical element, per-book Open Graph/Twitter values, valid Schema.org Book identity and correct first chapter ID. Fetch the declared image and verify content type, 1200×630 dimensions, source/derivative SHA and alt/rights. Reject missing/duplicated/stale metadata and generic-banner substitution.
4. Test the **same** direct path in the existing Reader on iPad portrait, iPad landscape, phone and desktop. Ensure opening lands in that book's authored contents, navigation opens actual paginated chapters, images/anchors remain source-correct, no horizontal clipping, direct URLs are visibly linked from the Bookshelf, and unrelated books/works are unchanged. Check machine catalogue parity without executing Reader scripts.
5. Admit exactly these files to one immutable owner-WLAN stage, with a source-lock guard, retained predecessor and terminal receipt. Independently read both HTTP and HTTPS routes, original image byte identities and representative unaffected neighbours. For production, require separate source/public rights and publisher approval, native EstatePublisher delivery and independent live public HTTPS+social card readback. A preview or local WebKit pass is not a public Facebook/share-cache acceptance.
6. On subsequent book edits or publishing, repeat the same compile + negative stale-artifact tests, update the machine catalogue with the new source identities, and source-review the exact release. Do not bolt on a second CMS, static template, analytics/tracker or continuously running scheduler.

## Important boundaries

- Governance at `governance.fountain.coach` is text-first and has its own authoritative routes and optional image policy. Do not add it to a Fountain Press release's Bookshelf when excluded, and preserve legitimate existing chapter citations.
- A book's illustrated source may remain **private** while its URLs and share previews are reviewed on owner-WLAN staging. Never advertise them as public or insert private assets into a public release without the separate source/rights gate.
- Story/essay/chapter links and their first-art policy may be separately maintained by their source owners; this book-level rule does not demote original in-text artwork, paragraph addresses, rights or chapter-specific share cards.
- Example acceptance numbers and routes are witnesses, not universal code contracts. Inspect the currently installed Press and published source revision before executing; reverify if either has changed.
