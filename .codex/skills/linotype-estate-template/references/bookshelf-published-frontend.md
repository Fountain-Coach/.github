## Think like a deterministic CMS, not a carousel

Existing Git/source admission, applicable Reframe/FountainStore editorial state and immutable published release records supply *data authority*. Fountain Press Linotype is the existing HTML/CSS/JavaScript frontend and compositor. Its Bookshelf is a derived **view** of admitted, published collections, not a hard-coded two-book or three-book navigation controller. A versioned immutable static HTML/JSON projection is sufficient for a public static site; do **not** require an always-on database API, another CMS, a new reader, or a second publisher.

Derive one status-bearing normalized publication snapshot distinguishing active-public, archived-public, staged/private and unadmitted works, with ordered book IDs, ordered active work IDs, archived-public identities, published/staged/private distinctions, source revisions, canonical routes, original image/rights/alt and media bindings. Preserve real public work templates for archive/direct routes while excluding them from the active shelf when the source records say archived. An initial page may embed the exact snapshot for deterministic startup; machine `catalog.json`, direct routes, metadata, contents and gallery must be projections of the *same source/release*, not competing lists.

### Rendering responsibilities

- **HTML:** reuse the existing source-authored work and the same Linotype semantic frame; each authored work template must be a top-level sibling, not accidentally nested inside a `library` template. Retained source is not automatic published/active membership. Never drop an original paragraph, illustrated source beat, editorial preface or source-linked audio binding to make a navigation fixture pass.
- **CSS:** Bookshelf scroll is horizontal *between whole published collection spreads*, not between contents and images as separate books. In landscape, each collection's complete contents faces its gallery; in compact/portrait there is one leaf with accessible Contents/Images presentation choices. Lists/gallery scroll vertically inside bounded regions; footer stays fixed. A subtle visible continuation cue can use next/previous *published collection labels* and page-edge geometry. Reject unreviewed side-tab/carousel ornaments, occlusion and cropping.
- **JavaScript:** calculate `collectionOrder`, adjacency, first/last controls, navigation status and page position from the same published snapshot as the rendered shelf. Maintain one selected work per collection shared across text and gallery; preserve horizontal position, both vertical scroll offsets, chosen presentation, Back/return and stable source addresses across reflow. Do not use source `<template>` insertion order, a hard-coded `['essays','first-readings']`, gallery count constants or ad-hoc `archivedEssays` exclusions as *independent* publication authority. A source-based integrity check remains useful but checks source-derived expected identities instead of freezing a historical count.
- **Published routes:** re-read `/`, `/estate/`, supported `/estate/read/library/`, `/estate/books/<id>/`, work deep links and `books/catalog.json` against one release identity. Resolve an intentionally supported legacy Bookshelf route to the active template or an explicit canonical redirect. Do not accept HTTP 200 on a stale route as parity. Distinct archived work URLs may remain old by design if honestly labelled, not misrepresented as the current Bookshelf.

## Finite verification before claiming a template fix

1. Read the **live** production/stage/snapshot and owner source before editing. Build `expectedPublishedBooks` and ordered works from admitted publication status and membership; compare exact IDs, order, active/archive states, rights, direct links and source/release revisions in every publicly reachable frontend projection.
2. Assert negative cases: published book omitted from root or legacy library, stale hashed Reader module, missing/deleted published entry, disallowed private entry, archived work relisted as active, source template incorrectly nested, wrong gallery-to-contents mapping, different selected work in the two projections, inconsistent catalogue order, bad source figure/share digest. These must fail before an immutable candidate is admitted.
3. Verify the **real same** Linotype template on desktop spread, tablet portrait and phone: visible horizontal continuation, pointer/touch/swipe/keyboard and fixed controls, nested vertical scrolling, Return/Back restores source/selection/scroll positions, direct-book paths open their exact source, no text/figure/audio loss or JavaScript startup exceptions. Automated WebKit does not replace a physical iPad Safari/VoiceOver witness.
4. Do not confuse the **documentation pin** with implemented frontend code, a staging release or production acceptance. Only EstatePublisher may activate an approved immutable artifact and provide typed release/rollback proof; source, WebKit and independent HTTPS must refer to the same candidate before declaring done.

**Scope and exclusions:** no new database, no new CSS design system or carousels, no alternative release service, no silent re-publication of archives, no direct authorial text edits, and no unaudited local reverse proxy offered as canonical staging. The skill update teaches what to inspect and how to prove it, not that it has already been implemented.
