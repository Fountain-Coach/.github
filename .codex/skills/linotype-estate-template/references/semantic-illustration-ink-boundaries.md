# Semantic illustration: measured frame, visible ink, and page flow

**Scope:** existing Fountain Press Linotype pages, source-owned SVG diagrams, Teatro Scores with labels, and their existing responsive reader projection. Read with [page-is-the-frame.md](page-is-the-frame.md) and, for Scores, [reader-navigation-and-score-composition.md](reader-navigation-and-score-composition.md). The source owner remains Fountain Press/edition Git, and this is a visual composition procedure, not a new renderer or Kit.

## Three separate measured boundaries

1. **The leaf's Satzspiegel (type area).** iPad **portrait** is the editorial golden reference for one complete leaf. Body prose, figure/image, caption and the resumed prose should share its measured left edge; compare *actual* bounding boxes, not nominal styles. A local measured-reader regression may use <=1.5 CSS px as the accepted tolerance. Landscape is a relationship between two complete leaves, not two squeezed web panels; phone reflows source without changing identity. An A4 Druckfahne is a separate print composition with deliberate correction space.
2. **The figure's visible outer frame.** For a framed diagram, align its **drawn** SVG border to the text measure, not merely the SVG `viewBox`, its HTML `img`, or a CSS wrapper. Secondary/unframed plates may use consistent optical canvas insets. Don't let a double CSS/SVG padding layer or a miniature book running head create accidental whitespace.
3. **The text ink *inside* a semantic rectangle.** Calculate the rendered bounding boxes for every label and every specimen line at its actual family, size, weight and browser. For a panel `[left,right]` and a glyph bounding box `[inkLeft,inkRight]`, require `inkLeft >= left + leftInset` and `inkRight <= right - rightInset`, with both insets visibly usable, **no letters crossing the border**. Also check top and bottom. The reference SVG's 336-unit-wide WEB READER panel at 27-unit Georgia type passed with >=28 units on the left and >=30 on the right, but **those example numbers are not universal page constants**. For other widths, scales, scripts and labels, choose meaningful insets from the actual measured composition.

An aligned `img` can still display letters crossing its **internal** frame. Outer-element checks **must not** be reported as proof of this third boundary.

## Smallest correction and acceptance

- Identify the **source-owned** frame, image, caption, source semantic block, active reader/edition and unchanged manuscript digest. Compare the actual stage with the selected accepted Reader; do not create an alternate book.
- Reproduce a failing glyph bound against the drawn frame. If the frame/label is conceptually correct but a line is too long, recompose **only the illustration's visual line breaks** (or adjust its intentional internal measure) without altering source words, shrinking all type, `overflow:hidden`, changing the reader shell, or clipping the failure.
- Verify the complete sentence after visual reflow remains exactly the source specimen. Preserve the other frames, its heading relationship, alt text, page/source-unit IDs, source prose, arrow and figure's geometry. For a Teatro Score, labels remain score-local and source-bound; do not present a static diagram as live Csound/MIDI2 state.
- In the **existing** WebKit/Chrome page test, measure `getBBox()` of each SVG `text` against the appropriate drawn `rect`. Include the heading and all visual lines, not only the first line. Reject any ink outside its frame, even where the whole SVG is correctly sized. Check both positive and a **negative fixture** reproducing the original overflow. Compare text-to-image-to-caption left edge and vertical rhythm on the composed folio, then navigate to the next/previous page and the containing book.
- Verify iPad portrait-sized, landscape facing-leaf and phone projections as appropriate, and check a responsive/accessible enlarged-text case when affected. The **physical iPad portrait Safari screenshot** is the primary editorial visual witness, but a screenshot of an *old failed* release is not proof that a newly corrected release has passed on-device. Record source/geometry/browser, WLAN release and physical-device evidence separately.
- For staging requested by the writer, use the existing production-derived Reader and immutable stage publication path with content digests, previous-release rollback and independent readback. Do **not** install another page engine, weaken the provenance guard, or infer public publication from a private WLAN result. End at the requested result; do not generalize into whole-estate refactoring.

## Recorded negative and positive case — 4 November 2026

- **Failure:** the writer's *physical iPad portrait* of *What Makes a Page Modern?* showed the WEB READER rectangle clipping/overrunning the source text. In `reader.svg`, frame x=710..1046, body starts x=740; first line ink ends ~1033 (only 13 units of right inset), second ends ~1047.17 **outside** the frame. Existing CSS/figure-alignment tests incorrectly passed; this is not a body Satzspiegel defect.
- **Smallest source fix:** `Fountain-Coach/fountain.coach@66ec9c5144953766bc99e7f9cf704b5ea17cf7a0` (PR #12): keep the words "A page is not a container in which words happen to rest." but re-lineate the right specimen as "A page is not a" / "container in which" / "words happen to rest." and align the heading and text at x=744. The left-hand A4 frame and full prose remain unchanged.
- **Measured acceptance:** WebKit/Chrome SVG `getBBox()` shows left inset about 34, minimum right inset about 44 SVG units; both composed the same source-owned illustration in the **existing** Reader. Candidate/v144 private WLAN HTTP+HTTPS digests and rollback were witnessed; neither a new Reader nor public promotion occurred.
- **Evidence limit:** that original physical iPad screenshot proves the **defect**; browser checks and private staged-byte readback prove the source change and certain geometry. The corrected page on the *physical* iPad remains an explicit separate writer-facing visual judgment, not retroactively accepted.

The transferable lesson is **ink must fit inside its *own semantic boundary***. It cannot be certified from a parent box, a CSS left-edge match, a screenshot of another release, or a passing compositor source-integrity check alone.
