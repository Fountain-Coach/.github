# FCIS official upstream OpenAPI dependency and evidence propagation

## Authority and scope

For every FCIS-owned adapter that calls an external provider, treat the provider's **official machine-readable API contract** as the authoritative boundary **when that contract exists and covers the used operation**. The interface implementation must be traceable to an exact upstream version. FCIS remains owner of the domain model, permissions, voice identity, source text, runtime Kits, publication and acceptance criteria. Do not promote a vendor API to FCIS governance authority; do not let a model guess the wire schema.

This is a general reusable procedure, **not a requirement that every provider publish OpenAPI** and not a speculative reason to delay otherwise accepted work. If the provider publishes no official usable OpenAPI for the interface, record `OFFICIAL_OPENAPI_UNAVAILABLE` with evidence and validate concrete official documentation/examples instead. Never invent a purported official specification, substitute an unofficial scraper, or broaden source scope to unrelated APIs.

## Procedure: a provider adapter from contract to verified examples

1. **Resolve the actual used interface.** Name provider, operation, transport (HTTP, WebSocket, events), owning repo and affected source paths. Read the provider's official specification, release and deprecation notes. Record an exact upstream commit/tag or version, trusted URL, content SHA-256, and licence. Record the transport/event lifecycle separately when OpenAPI only defines HTTP and message shapes.
2. **Depend on the upstream contract reproducibly.** Pin the exact original upstream bytes by immutable revision and SHA-256; derive only the transitive schema closure needed by the adapter. Check in a generated, reviewable projection plus lock file; implement repeatable, offline integrity/validation checks. The upstream bytes remain unmodified and upstream-owned. Do not fetch an unpinned `main` or a mutable model description during production execution.
3. **Validate actual provider boundary traffic.** Use the pinned schema types (or generated SDK types and schema checks) to validate outgoing request/event objects and relevant consumed incoming data. Fail closed on invalid consumed messages; classify unconsumed event types as out-of-scope, not falsely verified. Test negative schemas, required fields, codec/timing and state transitions independently. Record any upstream specification contradiction as a narrow named compatibility exception, pin the exact contradictory shape, and remove it on an upstream revision only after tests.
4. **Record successful example use at the correct boundary.** For each independently witnessed run, retain the code owner commit, official upstream pin, sanitized request/event class names, source and output hashes, terminal/transport receipt, and an executable offline regression fixture. Separate real traces from synthetic mock fixtures. Mark each layer independently: protocol conformity, transport delivery, persisted result, source fidelity, acoustic/media fidelity, artistic/user acceptance, accessibility, and publication. An unsuccessful layer never inherits success from an earlier layer.
5. **Propagate only the accepted, transferable lesson.** The source owner keeps provider-specific code, fixtures and raw evidence. Update the *existing* relevant canonical FCIS Skill under `Fountain-Coach/.github` with a short reference to the verified provider implementation and its run evidence. Preserve independent Git/marketplace/hosted selection state and the established Git-backed distribution (no ad hoc ZIP). Only accepted outcomes become positive examples; rejected outcomes become negative fixtures or explicit refusal boundaries. Do not generate a new Skill, runtime Kit or public edition merely to memorialize an example.
6. **Re-check drift when upgrading.** A provider change is a reviewed source change: update immutable upstream pin and schema digest, rederive projection, run all positive/negative fixtures, inspect deprecations, and separately witness a real provider call when runtime behavior changed. Never call a schema-only regression a live acceptance.

## First confirmed application: OpenAI Realtime in Satzfunk

- **Official schema:** [OpenAI's `openai-openapi`](https://github.com/openai/openai-openapi), OpenAPI 3.1.0, immutable commit `c2aecc2fbe1ddff3e7500a0eaa5c2bc4c19c5318`, `openapi.json` SHA-256 `d80bb28992f6c2a86876d866dcae0b1f15e130de94238592bc57a4a579448b5f`.
- **Upstream licensing:** Original OpenAI MIT attribution retained at `Fountain-Coach/Satzfunk/contracts/openai/LICENSE.openai-openapi`; follow-up PR #7 merged at `9a2f08032d2b71a9d50ad23ad4cdee5a23e09fe0`.
- **Owner-native implementation:** [`Fountain-Coach/Satzfunk` PR #5](https://github.com/Fountain-Coach/Satzfunk/pull/5), merged at `9de5b625bcd7653e1cc8ff83130a8799ae533eee`. Source `contracts/openai/realtime.lock.json`, 67 transitive schemas from seven selected Realtime event roots, `scripts/check-official-openapi.mjs`, `src/openai-realtime-contract.mjs`, and `src/openai-realtime-voice.mjs`; run `npm run contract:check` offline. The source owner's [bounded example](https://github.com/Fountain-Coach/Satzfunk/blob/main/examples/vergil-openapi-realtime-transport.v1.json) and [evidence analysis](https://github.com/Fountain-Coach/Satzfunk/blob/main/docs/ai/2026-11-01-official-openapi-realtime-contract.md) preserve both success and rejection.
- **Named official schema exception:** OpenAI's pinned `RealtimeResponseCreateParams.properties.conversation` has two overlapping `oneOf` alternatives for `none`/`auto`. The runtime validator narrowly uses `anyOf` **for that field only**, after checking the pinned upstream shape, without editing the original projected source.
- **What worked:** One previous `gpt-realtime-2.1-mini`/`marin` text-to-audio request completed, creating a 34.2-second private WAV. Source SHA-256 `447d628b03e6b72ac0ba8d815b9a2086dd19172ead869c0f898e7cefb96f1a08`; WAV SHA-256 `0f6219c329e4dec9b46799c1a2b90b846340e6c3d23b8a008b5254d89f1790f6`. Its synthetic event sequence is a **mock regression**, not a captured production trace. The new official schema check was passed on source-owned outbound events and valid/invalid mock inbound examples; it was not retroactively deployed during that earlier paid call.
- **What explicitly failed:** The user heard **an American female voice**. The required British male literary Vergil **was not cast or accepted**. The model's own generated transcript matching source does not prove independent audible word fidelity. No full Linotype edition, physical iPad/VoiceOver or public release follows.
- **Test evidence:** 44 Satzfunk tests passed, one skipped, zero failed; offline pinned upstream reprojection passed; provider code and source example merged. These prove the reviewed technical source and old transport receipt, **not** a new recording with the new schema gate and not the artistically rejected voice.

## Required evidence wording

Use `OFFICIAL_SCHEMA_PINNED` only for proven upstream bytes and reproducible projection; `EVENT_SCHEMA_VALIDATED` for actual adapter event values accepted by the pinned validator; `TRANSPORT_ACCEPTED` only when real provider delivery is witnessed; `ARTISTIC_REJECTED` or `ARTISTIC_ACCEPTED` only against independently observed voice judgment; `PUBLICATION_UNVERIFIED` until proper public readback. Do not compress these states into one "successful example" claim.
