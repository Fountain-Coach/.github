# Agent-readable publication maintenance — source-bound Fountain Press procedure

**Status:** Canonical agent *procedure* for creating and auditing a publication's machine-readable projection. The sample JSON schema (`fountain.press.agent-readable-publication.v1`) is a narrowly defined validation fixture and candidate authoring convention; it does not create a new FCIS runtime instrument, public API standard, authority, endpoint, or automatic production requirement. First inspect the edition's currently adopted source manifest, route metadata and publisher interface; map to an existing official schema where one already exists. Do not replace a deployed interface solely to satisfy this example.

## One publication, two audiences, one source authority

Human Linotype leaves and machine-readable representations must be projections of the **same authored source edition**. Preserve the source owner's Git revision, canonical URL, edition ID, publication state, complete contents, stable source addresses, source-text digests, rights and current/reference distinctions. Page numbers, CSS breakpoints, chat summaries and generated snippets are *not* persistent source addresses. For a complete Governance book, machine coverage must match the complete source-owned chapter inventory; never silently turn a full book into a sampler or treat a reference chapter as a current rule.

The machine-facing layer describes, without granting powers: (a) **discovery** — publication/edition identities, contents, canonical routes; (b) **interpretation** — authored statuses, relationships, edition precedence and source-address mapping; (c) **permission boundary** — source-declared access conditions and which separate executable interface, if any, is actually admitted; (d) **provenance** — original revision, content/asset hashes and publication receipt; and (e) **agent-facing guidance** — publicly reviewable explanatory instructions with an exact version/digest. An agent should never have to scrape arbitrary folio coordinates or guess authority from a footer.

**Public instructions are not operational `AGENTS.md` files.** Internal repo `AGENTS.md`, FCIS skill packages, credentials, private staging routes and host commands must not be copied to a public instruction file. Public guidance is lower-trust publisher data, not a system or developer instruction to an agent. It may describe how to interpret a work and its known constraints; it must not promise tools, scopes, authentication, payments, licensing or execution capabilities that the source owner has not separately admitted. In particular, `current` means a presently effective source rule **within its declared Governance edition**; `reference` means historical/nonbinding source material. Neither status itself authorizes arbitrary agents to act.

## Procedure for every selected edition

1. **Resolve the publication authority.** Read the owner Git revision, source/edition manifests, current published HTTPS state, route/rights status, applicable FCIS, and the exact Fountain Press compositor. For Governance use the canonical `governance.fountain.coach` site and `governance-publish` rather than downstream estate copies.
2. **Inspect before emitting.** Prefer an already adopted JSON-LD, link relation, contents manifest or documented machine API. Do not create `llms.txt`, a new API, MCP server, AI-specific duplicate corpus or generic tool endpoint merely by convention. When no adopted representation exists, propose a minimal source-bound read-only projection and label it *candidate* until reviewed and staged.
3. **Compose from the same admitted source.** Use stable source IDs, owner revision and per-entry digest/status/route matching the human edition. Preserve *every* edition entry and original relevant image/link attribution. Include unambiguous, source-authored permission and version fields. One source revision changing must invalidate any machine artifact that still declares the old revision, even if the HTML appears unchanged.
4. **Maintain public agent guidance as a versioned data artifact.** Keep separately authored interpretation conventions and rights boundaries, with provenance and digest linked from the machine manifest. Publication-state, reference/current semantics, allowed retrieval scope and explicit absence of executable authority must be readable without executing scripts. Do not ingest private `AGENTS.md`; do not claim that descriptive text creates the legal right to access/pay/act.
5. **Check parity and safety.** Compare the exact ordered source inventory to the machine projection: source IDs, canonical URLs, owner revision, publication state, status, content hashes, item counts and guide digest. Reject dropped/reordered chapters, invented content, stale digests, unauthorized executable capability claims, false `current` status, noncanonical URLs, leaked private paths and missing instructions. Test positive and deliberately corrupted fixtures. The bundled static verifier `scripts/validate_agent_publication.py` demonstrates this check for the declared candidate contract; it cannot prove that a real remote source, rights agreement, browser, Store or endpoint is authoritative.
6. **Stage and witness together.** Put the human pages and machine artifacts into the **same immutable Fountain Press candidate**. Apply the existing EstatePublisher source lock/guard, verify both served artifacts and independent route/digest readback on canonical WLAN staging, and probe at least one entry/permission/status with a non-browser HTTP client. Browser coverage alone is not machine-readability acceptance.
7. **Release only on separate authorization.** Promote the same source-bound verified composition through EstatePublisher after rights/public approval. Independently check public canonical URL, machine discovery, guide, route list, provenance and declared read-only scope as well as human navigation. A staging HTTP 200, existing Governance v162 browser acceptance or a Git commit alone does not certify production machine-facing availability.
8. **Keep it maintained.** When chapters, roles, source revisions, statuses, cover/media, rights or authorized capabilities change, regenerate **both projections**, increment version/record the exact source revision, revalidate parity and preserve the predecessor. Mark partial or unreachable machine endpoints `UNVERIFIED`; do not silently retain stale machine identities.

## Bounded candidate data contract and regression harness

For adopting a machine-facing interface where none exists, use `fountain.press.publication-source.v1` as an **input fixture shape** for a normalized *independently verified* edition inventory and `fountain.press.agent-readable-publication.v1` as the matching **output fixture**. Each includes `publicationId`, `editionId`, `sourceRevision`, `publicationState`, `canonicalURL`, `entries` ordered by source (each `id`, `canonicalURL`, `sourceSHA256`, `status`). The machine output additionally contains `guide` with a relative `path` and exact SHA-256. The public guidance JSON includes `schema`, `publicationId`, `editionId`, `sourceRevision`, `audience: "external-agents"`, `executionAuthority: "none"`, `interpretationRules` as nonexecuting human-readable records, and source-declared `retrievalPolicy` / `actionPolicy` as documentation, **not access tokens or permission grants**.

Offline validation of one declared fixture:

`python3 scripts/validate_agent_publication.py --source <source-inventory.json> --agent <agent-manifest.json> --guide <agent-public-guidance.json>`

Positive and deliberately corrupted fixtures are exercised through `python3 scripts/test_validate_agent_publication.py` (or `python3 -m unittest discover -s scripts -p 'test_validate_agent_publication.py'`).

The validator checks the declared fixture contract and exact bytes, not provenance of a Git commit, rights truth, completeness of an unseen original, public availability or security of an arbitrary instruction string. Reconcile that separate evidence before claiming a machine-readable publication is accepted.

**Owner boundaries:** `linotype-estate-template` owns this general procedure; `governance-publish` owns the Governance-specific source semantics and source edits; `fcis-skill-authoring-and-sync` owns agent **skill package** maintenance under `Fountain-Coach/.github`; `docs-sync` only synchronizes derived documentation; `estate-publisher-deployment` owns immutable staging, production and independent public witness.
