The root OpenAPI is the sole writable HTTP contract; the old `midi2-gpu-fabric/apps/estate-publisher/contracts/fcis-owner.openapi.json` is a predecessor, not an alternative authority. Native Go OAuth, WebAuthn passkeys, MCP, Host admission and a **fresh dedicated Go-native FountainStore** are the goal. Do **not** require an old Swift OAuth issuer, a migrated Swift snapshot, historical refresh families, a second persistence engine, PostgreSQL, SQLite, or unverified distributed replication. Preserve the issuer URL. Do not turn priority-two Stripe payment into a cutover gate.

**Contract-walk:** For each currently specified canonical OpenAPI HTTP operation, record `specified-only`, `Go-implemented`, `source-tested`, `released`, and `live-accepted` separately. Implement/validate exact Go method, path, authorization, input/output/refusal schema and owner/Host/Store evidence against the **pinned root OpenAPI revision**. For MCP, compare actual tools/list and tools/call with admitted typed Host registry and per-client grant; the OpenAPI contains no independent MIDI2 instrument/grant authority. When the root spec contains a target path with no Go handler, report that exact operation `NOT_ESTABLISHED` without inventing a separate service, and implement it only as a bounded slice of the accepted cutover. No hardcoded `host.describe` ceiling is justified by a predecessor tool list.

Use the existing `fountain-coach-instrument-creation` lifecycle for instrument implementation. This skill coordinates a bounded migration slice and selects an *admitted* deterministic Go build instrument; it grants no execution, deployment or Store authority.
