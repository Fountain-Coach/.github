# FCIS Go Runtime Migration

## First operational gate — stop the Invented-Prerequisite Loop

**Before any continue, code, new PR, test harness or security prerequisite:** preserve the owner's **original goal** and current finite DoD; inspect the live existing issuer/Host/Store authority and last accepted receipts first. FCIS prohibits **goal substitution → speculative prerequisite → implementation → test-based legitimization → new dependency → moving Definition of Done**.

For each proposed new dependency, identify the **observed failure**, binding existing contract, why the working route cannot satisfy the request, and the **smallest correction**. Without that evidence classify it **PROPOSED / non-blocking**, not a blocker. A passing source test cannot justify a new trust ceremony or establish machine admission. Do not weaken actual signatures, owner custody, grants, revocation or replay boundaries. Finish the original task and stop; use **reversal** of unjustified additions rather than building the invented prerequisite more thoroughly. See the [FCIS Founding Rule](../../../docs/FCIS-Non-Invention-and-Goal-Fidelity.md).


**Owner-selected standalone target (18 November 2026; Hetzner-first owner-continuity correction 19 November 2026):** The **peer canonical** `Fountain-Coach/.github/FCIS-STACK.md` and `Fountain-Coach/.github/FCIS-OPENAPI.json` jointly specify the native Go FCIS stack and HTTP wire surface. The root OpenAPI is the sole writable HTTP contract; the old `midi2-gpu-fabric/apps/estate-publisher/contracts/fcis-owner.openapi.json` is a predecessor, not an alternative authority. Native Go OAuth, existing owner-bound WebAuthn passkeys, MCP, Host admission and a **new dedicated physical Go-native FountainStore root populated by verified old-to-new logical state** are the goal. The **headless Hetzner server is the migration controller**; preserve the active owner, admitted machines, grants, revocations, issuer and protected SecretStore custody according to [FCIS Migration Security Profile](../../../docs/FCIS-Migration-Security-Profile.md). Do **not** depend on a Mac, invent a second enrollment UX, require the Swift issuer after cutover, or silently create a new owner/grants. Exclude unrelated services, PostgreSQL, SQLite and unverified replication. Stripe remains priority two.

**Contract-walk:** For each currently specified canonical OpenAPI HTTP operation, record `specified-only`, `Go-implemented`, `source-tested`, `released`, and `live-accepted` separately. Implement/validate exact Go method, path, authorization, input/output/refusal schema and owner/Host/Store evidence against the **pinned root OpenAPI revision**. For MCP, compare actual tools/list and tools/call with admitted typed Host registry and per-client grant; the OpenAPI contains no independent MIDI2 instrument/grant authority. When the root spec contains a target path with no Go handler, report that exact operation `NOT_ESTABLISHED` without inventing a separate service, and implement it only as a bounded slice of the accepted cutover. No hardcoded `host.describe` ceiling is justified by a predecessor tool list.

Use `fountain-coach-instrument-creation` for FCIS-KIT instrument development and eventual admission. **Do not require an FCIS Host grant to compile or test trusted Go source in an independent, owner-authorized development sandbox.** A development build is not an instrument invocation and confers no runtime authorization, deployment, or FountainStore terminal evidence.

Fail closed on untrusted source, inadequate isolation or unavailable authentication; report those precise facts.

**Release separation:** a protected Git merge, GitHub green `build`, owner Git acceptance, signed Go artifact, FountainStore terminal receipt, and public `fcis.fountain.coach` OAuth/MCP acceptance are six **different** claims. ## Separate development verification from production admission

**DEV lane — trusted source tests, no FCIS grant:** For a user-authorized Go implementation/test request, run the existing fixed source-owned verification script on a clean, pinned checkout in an unprivileged isolated Ubuntu environment, with `GOPROXY=off` and offline pinned dependencies and no production credentials, processes, Stores, writable deployment roots or network listeners. A controlled terminal/sandbox here is an owner development tool, **not** a fallback `workstation.go.verify` dispatch. Do not ask the production service being replaced to authorize this work. Report source revision, clean-tree check, toolchain, fixed test commands and actual exits as `DEV-VERIFIED` or `DEV-FAILED`. Tests may not fabricate an FCIS Host receipt.

**PRODUCTION lane — admitted capability and independent release:** Require signed owner/Host grants, typed FCIS-KIT admission, exact artifact/Store terminal receipts, separately authorized HTTPS/Caddy cutover and independently verified rollback **only** when invoking production Host effects or promoting the release. Missing production Host `workstation.go.verify` is not a blocker to DEV verification; a healthy Go test is not permission to perform a production operation.

**No authorization laundering:** Do not take arbitrary developer commands, source supplied by untrusted PRs, sensitive environment variables, SSH credentials, unrestricted network access, or host-mounted production data into the test lane. The reviewer-selected exact Git commit, isolated worker user, fixed script, bounded time/resources and recorded source provenance are mandatory; use the existing toolchain and cache, not another execution framework.

## Mandatory finite execution contract — stop the loop

Apply on **every** invocation, including a bare "proceed." The owner's requested outcome, not discovered dependencies, is the scope. This is a hard execution gate, not optional advice.

1. **One slice, one Definition of Done.** State the source, exact revision and nearest test acceptance. Resume the owning `PLANS.md`; do not turn dev verification into a separate Host migration initiative.
2. **Choose the lane before execution.** DEV lane: user-authorized review of source and isolated Ubuntu `scripts/fcis-ci.sh go`, no FCIS issuer grant. PRODUCTION lane: inspect the actual admitted Host operation, owner signer, Store binding and release control before any privileged effect. An unavailable production grant never suspends an independently safe DEV test.
3. **15-minute hard limit per bounded slice.** Make one implementation attempt and one focused retry against a reproduced predicate. At most one full native/SwiftPM rebuild if separately required on an approved external host; do not compile on the MacBook Pro, re-run identical terminalTimeout probes or start a Swift bridge.
4. **Freeze dependency scope.** No replacement runtime permission engine, plugin/Skill identity, CI server or Swift Host adapter solely because the Go development tests are not yet accepted. Stop only at an observed execution failure, exhausted bounded retry, unsafe source/isolation, actual privileged authorization refusal, or missing requested tool.
5. **Stop on the first terminal condition** for the selected lane. A Go test failure yields a source-addressed correction, not a request to enroll a production Host. A production admission failure yields a precise permission/evidence blocker, not an excuse to test through production. Neither may claim the other's acceptance.
6. **Finite handoff.** Report revision, commands, exit status, receipts actually available, source-test versus Host/release states, and the first unmet acceptance predicate. Mark `DEV-VERIFIED`, `DEV-FAILED`, `SOURCE_UNAVAILABLE`, `LIVE-ADMITTED` and `PRODUCTION` distinctly.
