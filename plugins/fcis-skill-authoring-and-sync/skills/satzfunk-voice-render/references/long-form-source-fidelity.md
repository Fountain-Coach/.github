# Full-length spoken editions — source-verified automatic repair

Use this procedure for complete narrated works when an owner-native speech instrument exists. The procedure is reusable; the reviewed native Swift reference is [midi2-gpu-fabric PR #85](https://github.com/Fountain-Coach/midi2-gpu-fabric/pull/85) merged to main on 1 November 2026. This reference does not publish any private audio and does not make the short Satzfunk Realtime sample the full-chapter backend.

## Source and execution gate

1. Inspect the owning FCIS Kit, manuscript, original narrator voice specification, source SHA-256, current official provider contract, authorized cost/credentials and the exact scenario. Use the existing permitted provider route; never switch speech endpoints/models or transport protocols based on an old audition recipe. Preserve source text as immutable.
2. Segment the *exact* admitted reading at stable source passages and retain a digest for each input string and native WAV segment. Record a complete original result and its per-segment receipts before any correction. Keep the original WAV and derived MP3 unchanged, private and replayable.
3. Obtain an **independent transcription of each actual recorded waveform**, not the synthesis provider's generated-text receipt. Compare source against that witness, classify exact normalized words, demonstrably same-speech orthographic variants (e.g. British/US spelling), proper-name recognition ambiguity and substantive lexical changes. Spelling equivalence is explicitly bounded; do not accept `unresolved` as `resolved` or `Teatro` as `truth`.
4. Recheck mismatches using the already recorded waveform and a bounded *vocabulary-only* recognition hint for proper names. **Never include the expected manuscript passage as a transcription prompt**: that would bias the independent witness. A terminology-aware match is still only an ASR witness, not proof of infallible acoustic identity.
5. Regenerate only still-lexically-unresolved passages using the *same approved narrator implementation*. Use host-approved paid budget and exclusive attempt IDs; give **every unresolved passage one first attempt before any second**. Persist each candidate WAV and audio digest. Independently transcribe fresh candidate audio; when just the proper name remains ambiguous, perform a terminology-aware **candidate-audio recheck before paying for another take**. Do not rewrite the written manuscript to match recognizer output.
6. Accept replacement audio only on a fresh source-aligned independent witness. Record retained/replaced/failed segment identities, source and audio digests, and negative results. Preserve original audio for any failed candidate; block assembly of a 'source-aligned' master while any passage remains unresolved. Never silently exhaust or reset a payment budget or reuse an attempted billing identity.
7. Assemble and digest an entirely new private WAV and optional MP3 only when all selected passage witnesses align. Separate the claims **`independent transcript-aligned`**, **`artistically accepted`**, **`host/AX live accepted`**, **`released`** and **`publicly published`**. Passing one is never proof of the others. Do not put private sources, credentials, audio, or receipts in a public Skill or Git repository.

## Witnessed transfer and failure boundaries

The original Vergil chapter completed fourteen segments; independent transcription initially gave six strict matches and eight discrepancies. Bounded contextual rechecks avoided unnecessary recreation of name-only disagreements. An initial correction pass rightly withheld the master while passage 5 still transcribed as `theatre`. A second independent **audio** transcription of the already-rendered candidate with the name `Teatro` supplied as vocabulary settled the disagreement without further synthesis. Passage selections **3, 5 and 12** were replaced and eleven original WAVs retained; **14/14 normalized independent transcript comparisons** passed. WAV duration was about **498.97 s** and the source/manuscript was unchanged. This proves a specific private transcript-alignment result, not perfection of the audible performance or authorization to publish.

**Positive regression:** the source-aligned fourteen-segment case retains known-equivalent originals, rechecks a candidate's own audio before second synthesis, fairly distributes first attempts, assembles only with no unresolved segments and records both positive and negative receipts.

**Negative regressions:** (a) self-reported TTS transcript cannot pass independent verification; (b) lexical omission/substitution cannot pass orthographic normalization; (c) name ambiguity cannot be made 'correct' by rewriting source or leaking expected words to ASR; (d) a spent budget with unresolved segments cannot yield a verified master; (e) successful waveform/transcript matching does not grant artistic, host, rights or production status.

Reader binding and WLAN/public publication belong to the current Linotype and EstatePublisher skills, not to this voice-rendering procedure.
