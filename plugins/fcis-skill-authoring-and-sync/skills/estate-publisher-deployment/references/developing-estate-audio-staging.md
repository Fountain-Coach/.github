# Preserve the developing estate when staging narrated books

Use this when the requested outcome is to add a source-bound narrated edition to an evolving Bookshelf or Linotype reader on the owner's existing WLAN staging server. It supplements the current [WLAN staging](wlan-staging.md), canonical [Linotype source/staging/production lineage](../../linotype-estate-template/references/development-staging-production.md) and the installed EstatePublisher owner operation. It **does not** convert a private preview into public release authority.

## Correct target before any mutation

1. Resolve the user's actual intended reader generation and internal work identity. Independently inspect the existing stage symlink, served DOM and current registration, current Git development branch, accepted plan and the public site's existing deployed version. If the new Bookshelf and a legacy essay share a title, select the one the writer is **developing**. Do not infer that the public published version is the development baseline merely because it already has a functioning route.
2. Record the exact source/branch/commit, predecessor stage identity, all affected paths, rights and media authorization, and the stage-only developments that must remain intact. The stage predecessor alone does **not** prove a separate writer-requested production-first guarantee. When that particular guarantee is requested, apply the existing Linotype production-baseline gates to the selected affected scope; do not erase current accepted stage work in the name of that gate.
3. Verify the source-bound narration input from the owning Kit's retained, privately verified master: manuscript/source digest, **actual** audio digest, edition/voice status, private manifest and reusable permitted playback path. A source-aligned ASR result is not an artistic/public release approval. Never stage private source, unreviewed WAV, API credentials or a public link to private media.
4. Build one **immutable candidate** from the correct active development staging predecessor, applying only the declared Git-controlled reader/audio delta and explicit WLAN transforms. Preserve foreign-owner pages, illustrations, collections, galleries, source text, current reader engine and unrelated stage-only features. Compare full candidate/predecessor inventories: added, modified, deleted, preserved and expected media SHA-256. Revert a wrongly attached legacy audio control only within its scoped correction; do not delete published essays or unrelated release data.
5. Activate via the existing approved WLAN transport, preserving the preceding symlink/release and rollback. Read back live stage identity, relevant HTTPS routes, source/manifest/media hashes and stage services; **do not stop at HTTP 200**. Test the *actual internal reader route*, Play/Pause, page-turn continuity, leaving the source volume, and responsive layout with current browsers. Verify seeking separately if requested/advertised; a server that returns a complete MP3 instead of byte ranges may play normally while refusing seeks. Adjust the existing player's source-owned media transport when justified, not the host topology.
6. Keep public production unchanged unless separately authorized. Record the exact stage and source revision, native delivery/receipt state, browser witness and residual unknowns. Never call a hand-copied WLAN overlay an EstatePublisher production release. Where a staging operation uses the simple approved WLAN lane, state what the active symlink/readback prove and what the absent production native receipt does not.

## Regression evidence from the corrected Teatro stage

The initial rollout put Vergil's new recording into the **old standalone essay** and passed local technical browser tests. The user rejected its editorial target. [That PR #5](https://github.com/Fountain-Coach/fountain.coach/pull/5) was closed without merge. A corrected bounded candidate integrated the pre-existing `teatro` volume in the **new Bookshelf** using the existing SatzfunkPlayer; [PR #6](https://github.com/Fountain-Coach/fountain.coach/pull/6) merged into the active developing reader branch. The old stage-only audio controls were reverted, the valid new reader and 14-segment recording preserved, and previous immutable releases kept for rollback. The author-owned WLAN v120 passed four Chromium/WebKit desktop/phone reader/audio tests.

**Negative gate:** a correct MP3 checksum, responding hostname and working audio control on an obsolete public-style edition **must not** count as success for a request to extend the new Bookshelf. Neither a stage Git diff nor a green browser test alone proves rights, production lineage, artist approval, physical iPad accessibility or public release.

**Positive gate:** confirmed developing work identity + exact source/media digests + bounded immutable candidate inventory + active stage readback + browser witness of the selected reader + preserved rollback + explicit public/not-public status.
